# ProLIF Web

`@ramithuh/prolif-web` is an **unofficial**, browser-native TypeScript port of
the deterministic interaction rules in [ProLIF](https://github.com/chemosim-lab/ProLIF).
It is intended to let applications such as Weaver calculate interaction
fingerprints locally, without a Python API or server-side chemistry worker.

This package is an interaction engine, not a viewer. PocketScope and Weaver
remain separate applications that consume its results.

## Compatibility target

The initial target is ProLIF 2.2.x. Upstream Python ProLIF remains the reference
implementation and parity oracle. Rules are ported individually, with fixtures
that compare atom participation and geometry against upstream behavior.

The browser alpha provides:

- stable molecule, feature-match, and interaction metadata contracts;
- browser-safe vector geometry;
- the generic distance, angle, ring-plane, and van der Waals primitives;
- an RDKit.js SMARTS adapter;
- Python-parity-tested implementations of hydrophobic, H-bond, halogen-bond,
  ionic, cation–π, π-stacking, metal, and van der Waals interactions;
- the same default interaction family set as Python ProLIF 2.2.1.

The compatibility manifest remains the source of truth. A rule is not marked
implemented until the browser result has been compared against a fixture
generated by upstream Python ProLIF.

## Development

```bash
cd web
npm install
npm test
npm run typecheck
npm run build
```

## Python parity gate

The committed reference fixture is generated by Python ProLIF 2.2.1 from the
same molecular fixtures used by its interaction tests. The browser suite checks
interaction multiplicity, participating local and parent atom indices,
distances, rule-specific angles, positive and negative examples, and inclusive
distance cutoffs across all implemented interaction families.

```bash
# Requires Python ProLIF's development environment.
npm run parity:refresh

# Runs the browser checks against the committed reference.
npm run parity:test
```

Passing this gate establishes parity only for rules marked `implemented` in
`src/compatibility.ts`; it does not imply that planned interaction families are
already available.
